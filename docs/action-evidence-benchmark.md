# Offline action evidence replay

From the Look checkout, run `python scripts/benchmark_action_evidence.py`. If Write is not the adjacent `write` checkout, pass `--write-root C:/path/to/write`. The script uses the two repositories' current code, a synthetic design, and a temporary directory. It does not connect to a database or a live Codex conversation, or open an approval window.

The fixture requests 32 exact values across 8 nodes. The fragmented route makes individual Look reads on both the published copy and the draft. The batch route reads the published targets once, exports their handoff with the current draft, and validates it in Write. The fixture sets different business-action and draft-row codes. The replay verifies the values in both routes, checks that the batch loads the design once, and checks that Write matches all current targets without a second Look pass or inheriting authorization or approval.

The fragmented route used 64 evidence calls and 45,600 bytes of structured JSON. The batch route used two Look calls and one local Write validation, returning 15,797 bytes. These are reductions of 95.31% in evidence calls and 65.36% in structured response bytes on this fixture. The script exits unsuccessfully if either drops below 50% reduction or evidence differs. The byte counts use indented UTF-8 JSON and exclude transport framing and candidate output.

Pass `--native-bridge C:/path/to/frontend/dist/action-design-compiler/bridge.js` to generate the first JS candidate after Write accepts the same handoff. The native compiler applies a guarded parameter update and inserts a `CustomExt` comment on that fixture. One local run took 6.97 seconds for the compile call and 7.39 seconds from the start of the Look batch to the checked candidate, including Python worker startup. This is a local timing sample, not a performance guarantee. It excludes model and network latency, the approval workflow, and runtime testing; it is not a comparison of native compile speed between routes.
