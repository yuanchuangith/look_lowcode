
# GXP 低代码排查业务关系图与自动复用

## Summary

通过持续排查，把每次得到的业务实体、关系及字段流转证据增量融入同一张全局业务图，而不是仅保存互相独立的“问题结论 + 小图”。同一业务对象、动作、表、视图或字段在不同排查中出现时，应通过稳定身份复用已有节点；不同业务经已确认的调用、引用、读写、字段映射等关系逐步连接，形成可查询的业务关系网和数据流转图。

图谱只保存结构与证据元数据，不保存真实业务行、凭据、连接信息、完整参数或完整生成代码；不写业务库、动作设计、草稿或发布状态。业务图只能反映已覆盖、已取证的范围，不能在排查尚未覆盖全平台时宣称已经完整。

## 全局图谱实施计划（0.5.0）

### 一、目标与实施范围

将 0.4.1 案例证据缓存升级为持续累积的全局图谱：每次排查贡献实体、关系和证据，不同案例经共享实体自动融合；业务关系网和数据流转图是同一底图的不同投影。阶段一内容保留为历史，不作为全局图完成的依据。

资料来源锁定为排查结果＋围绕当前问题按需读取已有 CPM、Schema、源码目录。发现缺口后有界自动补查，确认后才连边。展示为本地 MCP＋Mermaid，不开发交互网页或远程图服务。只持久化结构、定位和证据元数据，不保存业务行、凭据、完整参数、完整生成代码，不写平台设计。

### 二、全局图模型与存储

- Python 标准库 SQLite，系统数据目录 business-graph.sqlite3。实体、事实、支持证据、案例观察、目录、待取证任务和审计分开存储；事务增量提交，外键、WAL、5 秒锁等待。
- 实体 ID 由 scope、环境、类型和规范化稳定业务身份生成。动作使用 RefId；节点使用动作／分组／node_key；页面／流程用平台稳定 ID；数据对象包含数据源／Schema／对象名，字段再含列名；报表用所属页面及组件稳定 ID。名称、行号、发布版本仅作为属性／证据。
- 禁止名称猜合并：不同环境、数据源和表的同名字段隔离；业务对象须有明确标识或已确认映射。缺身份保留待消歧，不自动融合。
- 事实边独立于案例，由两端、关系类型、方向、条件签名和字段映射签名确定身份。签名来自规范化结构，不用描述文字或发布版本；同事实复用并追加支持，不同分支／转换保留平行边。
- 每份支持集合记录来源案例、确认级别、指纹和完整动作／Schema／源码版本依赖。任一完整有效集合可支持事实；撤销案例或版本仅撤销对应支持，全部失效才退出当前事实图，历史保留。
- 目录确认存在的实体允许没有业务边，标为目录实体；孤立或片段可以保留。候选连接只进待取证清单，不因暂时孤立而删除或补猜关系。

### 三、查询接口、算法与自动化

#### 工具接口

保留 search_business_logic_graph、upsert_business_logic_graph、invalidate_business_logic_graph 的旧输入／返回字段，通过适配层写 SQLite；upsert 新增 format_version=3 的实体／事实／证据增量，返回新增、复用、更新、待复核数量。

新增 get_business_graph（实体／关键词／范围子图、投影、邻域及目录开关）、trace_business_data_flow（上游、下游、有向起终点路径）、analyze_business_graph（分量、孤立、循环、缺口、覆盖及有界建议）。本地 stdio 从 38 增至 41；HTTP 保持 16，不暴露图工具。图结果含统一 ID、证据引用、版本、Mermaid 和截断；历史须复核当前发布。

#### 投影与算法

- 业务投影保留调用、触发、引用、关联、依赖、读写、展示；数据投影只沿已确认生产、读取、转换和字段映射。contains／belongs_to 不充当字段流转；未确认输入／输出绑定的调用不进血缘。只有表级来源时标 dataset_level。
- 弱连通分量检查片段，BFS 查可达路径，SCC 查循环；支持收缩展示但不删除真实回写／反馈。静态可达和实际执行明确区分。
- 缺口分业务独立、合法边界、身份未消歧、证据缺失和证据过期。不要求全图连通，不把所有孤岛报为 Bug。
- 邻域默认 2、最多 5 跳；最多 200 节点／400 边／256 KiB。路径默认深度 8、最多 20、最多 5 条。到上限明确截断并返回前沿，不截半条支持集合。
- 孤岛分析必须完成声明范围邻接检查；若扫描预算截断，返回未完成，不能把查询截断造成的孤立当真实孤岛。

#### 排查闭环

1. 解析实体，查历史邻域和可用目录，复核当前发布及必要只读证据。
2. 确认的实体、事实与完整支持集合事务融入全局图。
3. 分析新片段与已有业务的连接和缺口。
4. 每次用户请求最多 3 次额外取证调用、1 跳、30 秒；共享 request_id，优先已有目录、源码与精确设计，不自动查业务行、不递归补查。
5. 目录缺失、过期、来源不明时保留任务，不全量刷新。成功再次幂等融合；失败不撤销已确认事实，不阻断正常报告。

覆盖率只对明确已知目录、scope 和快照版本计算，不宣称未知全平台完整。

### 四、测试与验收

- 跨案例 A→B、B→C、C→D 融合为完整可查链；公共实体唯一，逐边可追溯。
- 稳定身份相同而名称不同合并，同名不同表／数据源／环境不误并，缺身份不猜。
- 重复提交幂等，多案例支持并存，撤销一份不删其他有效支持；跨动作任一依赖变化仅影响依赖集合。
- 孤立实体可存，确认桥接后分量合并；边界不误报，循环真实保留且能收缩。
- 结构归属和未绑定调用不制造血缘；表级／字段级、条件／转换、静态／实际执行区分。
- 补查次数、深度、时间受限；截断不产生假孤岛／半证据；锁超时、坏库、工具失败正常降级。
- 兼容旧契约、脱敏多案例夹具、并发事务、迁移幂等、敏感门禁，41／16 工具注册及真实 MCP 协议验收。

### 五、迁移、交付与默认约束

首次初始化持迁移锁建临时 SQLite，按源文件指纹导入现有有效 JSON，校验后原子发布。JSON 和 .legacy-v1.json 保留原样，不双写；重复初始化不重导。只有稳定身份与证据明确的事实入全局图，无法转换案例保留检索和待复核原因，不补造身份、环境或指纹。

顺序：统一身份／事务融合／旧工具适配 → 两种投影／路径 → 目录／缺口／有界补查，各阶段测试后推进。算法仅标准库，无图服务或 NetworkX。scope 默认当前 Schema 配置，新源须明确；环境默认 development，不根据问题文字重标。

交付版本 0.5.0，同步技能、契约、安装文档和验证脚本。通过仓库安装器更新，验证插件清单、实际 MCP 41 工具、CPM 版本／状态；新建 Codex 线程加载。图缓存失败继续只读，不双写旧 JSON，不改变业务数据与凭据。

详细 v3 输入与门禁：skills/gxp-lowcode-debug/references/business-logic-graph.md；实现与验收记录：docs/business-logic-graph-contract.md。

### 2. 增加 3 个本地 MCP 工具

在 `mcp/gxp_core/service.py` 和 `mcp/server.py` 增加：

- `search_business_logic_graph`
  - 按问题关键词、动作、页面、表、字段和状态检索；
  - 返回结构化关系、证据摘要和 Mermaid；
  - 明确标记“必须重新核对当前发布副本”。
- `upsert_business_logic_graph`
  - 仅接受已确认状态；
  - 校验锚点、证据指纹和敏感字段；
  - 重复写入不产生重复记录。
- `invalidate_business_logic_graph`
  - 用户明确指出关系错误、发布设计变化或证据失效时，将关系标记为失效；
  - 不删除审计记录。

这些工具只注册到本地 stdio MCP，不注册到 HTTP MCP，避免本地诊断缓存被网络接口暴露。

### 3. 修改 `gxp-lowcode-debug` 技能流程

## 阶段一 Acceptance Criteria

- 新装或升级后，本地排查会自动先查关系图。
- 排查完成后只自动保存已确认的结论和证据链。
- 同一问题重复排查不会重复生成记录。
- 当前发布设计发生变化时，不会直接复用旧结论。
- 关系图输出同时包含结构化节点、边和 Mermaid。
- 缓存异常不会阻断正常只读排查。
- 不产生任何业务数据库写入、动作设计写入、草稿写入或发布操作。
- 岗位培训“取消/关闭后结束日期”的排查链路可以作为已确认关系被复用。

## 阶段一 Assumptions

- “用户的自动动作”由技能在最终确认后自动调用本地 MCP 写入工具完成，不在每次中间 MCP 调用时写入。
- 关系粒度采用“业务结论 + 证据链”。
- 只迁移已有缓存中的已确认关系，候选关系必须重新验证。
- 关系图属于本机诊断缓存，不跨电脑、不上传服务器、不参与业务运行。
