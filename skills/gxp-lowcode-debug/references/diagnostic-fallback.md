# 缺证据与故障时的有限补查

出现 `evidence_gaps`、`fallback`、截断、未验证或工具错误时读取本页。只补当前结论必需的证据，已确认事实可继续复用；缺完整平台证据不等于必须扫描全平台。

## 补查预算

跨工具补查由技能编排，不存在通用工具执行器。对同一排查问题记录已尝试的工具＋参数、起始时间、累计耗时及剩余预算；换工具、换分页或换参考不重置预算。最多额外调用 3 次、总预算 30 秒；既有图谱补查更严格的次数、跳数和时间限制同时生效。正常主线定位不因兜底限额被禁止。

`next_read` 是建议，不是任意执行授权。只执行当前已授权范围内的只读请求；缺必要参数时先补已知标识，禁止猜造。支持超时的入口把超时设为剩余预算与原上限的较小值；不能控制超时的入口只列建议，不自动启动。不得把刷新默认 300 秒当作 30 秒内可控补查。预算耗尽、相同路径已失败、需要新授权或无法取得关键证据时停止自动补查，保留准确的待执行请求。工具耗时优先用 `total_elapsed_ms`，并计入调用之间已消耗的墙钟时间。

`resolve_table_relation` 的 `live_timeout_ms` 只限制查询工作期限，不能取消连接池等待、建连、ping 或连接归还。只有调用外层还能按剩余墙钟时间停止等待或取消请求时，才自动执行该补查；仅能传 `live_timeout_ms` 的 MCP 调用只返回建议。不要把查询超时参数当作整个调用的墙钟保证。

## 固定补查路径

| 缺口 | 最小下一步 | 结论边界 |
| --- | --- | --- |
| 摘要、记录或顶层元数据缺失 | 当前节点/字段精读；必要时使用原参数和 `next_cursor` | 校验指纹、偏移和相关页；`has_more=false` 不等于证据完整 |
| 全量 Schema 刷新失败，源/目标表列已核实 | 同一 `resolve_table_relation`，四项表列参数原样保留并设 `force_live=true`，`live_timeout_ms` 取剩余预算（100..30000） | 只证明指定目标，不证明全局唯一；策略或唯一键证据不可用则未验证 |
| Schema 目标列缺失 | 当前表的 `describe_table`，按证据明确列 | 不猜字段映射，不重复全库刷新 |
| CPM 刷新失败 | 使用响应自动返回的 `stale=true` 旧候选；已有快照也可显式 `refresh_if_stale=false` | `snapshot_candidates_only`，不能确认当前发布、运行或不存在 |
| 源码某层失败 | 保留健康层；有精确锚点时用兼容受限搜索脚本 | 不用旧索引行号配新源码，不据局部结果闭合跨层链路 |
| 结构化工具故障 | 一个能够回答同一问题的替代结构化入口 | 原调用错误不代表业务 Bug；不重复相同失败路径 |
| 结构化工具无法表达必要查询 | 表列已核实时，说明原因后使用受守卫的窄 `readonly_sql` | 不绕过只读、环境、行数或查询超时限制 |
| MCP 不可用 | 仅在兼容 CLI 已存在且可受控超时时使用同等只读入口 | 同一数据库故障不能靠 CLI 解决；不得读取连接密码 |
| 缺生产或页面运行证据 | 继续独立静态检查，一次列齐当前阶段的最小生产只读 SQL／页面证据需求 | 原环境不重标生产；页面授权仍按运行证据规则执行 |

## 停止时的输出

分别列出已确认事实、候选原因、影响结论的缺口、已尝试路径、停止原因和最小下一步。不要写“没有问题”“已运行通过”或未经证明的修改位置。`fallback` 只描述补查情况，不覆盖 `response_complete`、`evidence_complete`、游标或业务状态。
