# JS Reverse 运行页面取证

## 触发条件

仅在以下情况使用 `js-reverse-extension`：

- 当前发布 ActionDesign、生成 C# 和只读业务数据均无法解释实际页面症状。
- 需要确认按钮实际调用了哪个动作、请求参数是否正确、响应在哪里丢失，或前端组件是否改变了字段值。
- 用户明确要求查看已打开的相关页签。

若静态证据已足以定位，不要扩大到浏览器取证。

## 连接与授权

1. 说明缺少的运行证据，例如“需要确认岗位培训任务列表实际请求的筛选参数和响应”。
2. 请用户在 Chrome 打开有问题或包含相关信息的 HTTP(S) 页面。
3. 请用户点击 JS Reverse 扩展并把目标页签开关设为 ON。
4. 若 MCP 尚未授权该站点，请用户从扩展弹窗生成一个六位一次性码，并以 `$connect-js-reverse 123456` 提供。
5. 按 `connect-js-reverse` 技能执行：先检查 bridge，授权精确 Origin；授权工具不可用时才兼容使用 `pair_extension`；再次检查 bridge 并用 `select_page` 列出显式开启的页签。
6. 没有六位码、码已过期或目标页签未开启时，停止连接步骤并准确说明缺少什么；不要猜码、启动 Chrome 或使用远程调试端口。

授权只适用于返回的精确 Origin。不得把 `paired=true` 当成目标 Origin 已授权，也不得查看用户未开启的其他站点页签。

## 只读取证顺序

1. `select_page` 确认目标 URL、标题和页签索引。
2. 读取当前页面可见状态、控制台错误和已有网络请求。
3. 若需要复现，请先清空网络请求缓存，再请用户执行一次最小复现；不要代替用户触发会写业务数据的操作。
4. 只筛选与症状有关的 XHR/Fetch：动作 code/RefId、接口路径、任务 ID、周期 ID、详情 ID、用户 ID 或错误文本。
5. 需要时读取请求/响应正文和调用栈，追到前端组件、公共动作或后端接口。
6. 若仍无法定位，才搜索已加载脚本或创建临时 hook；记录 hook 范围，避免更改页面持久状态。

## 证据边界

- 不回显 Cookie、Authorization、密码、连接串、完整用户清单或无关响应正文。
- 仅摘录定位所需字段和值，并区分请求参数、响应数据、页面计算结果和 ActionDesign 配置。
- 不点击保存、提交、发布、推送、创建培训、完成培训、删除或更新按钮。
- 浏览器页面出现的设计 JSON 仍按草稿/发布副本语义解释；页面编辑态不等于运行发布副本已变化。
- 页面/网络证据只能证明该次运行或该次复现；不能代表所有历史数据。

## 输出补充

```text
运行页面：<精确 Origin、页面标题、目标 URL；省略敏感查询值>
页签授权：<已开启且已授权 / 仅开启未授权 / 未开启>
复现动作：<用户执行的最小步骤；若未复现则写仅检查现状>
网络证据：<方法、接口路径、关键请求字段、状态码、关键响应字段>
控制台/脚本证据：<错误、调用栈、组件或函数位置>
与低代码链路的对应：<动作 code/RefId、分组、画布节点或后端接口>
结论边界：<已定位根因 / 仅定位到前端组件 / 仅定位到接口 / 仍缺少何种证据>
```
