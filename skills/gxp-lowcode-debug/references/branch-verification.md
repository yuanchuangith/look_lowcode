# 控制流与交互分支复核

出现两层及以上嵌套、分支／结束节点归属，或用户描述点击、选择、留空、批量编辑等具体交互时读取。主技能中的控制流门禁始终生效；这里补充取证与恢复步骤。

## 结构与场景

- 在目标时点的运行发布副本调用 `inspect_control_flow`，读取完整闭合块；不得用相邻节点或平铺 `parent_path` 猜 `Else/ElseIf/IfEnd`、循环结束、`Catch/Finally` 的配对。
- 输出简短 `views.tree_text`，明确 `root_block`、`matched_branch`、`matched_end`。结构无效只能列“结构候选/待确认”，不判 Bug、不可达或给修改位置。
- 判定分支 Bug 须同时有当前运行副本、有效结构、用户明确规则、最小 `scenario_matrix`，且期望路径与三态静态实际路径矛盾。场景至少覆盖每个业务分支与空值边界，不要求指数穷举；`unknown`、函数、表达式和查询不是实际运行证据。

## 证明本次交互命中

1. 从用户实际操作还原输入；“未选关联对象”和“选择组件后已有值”是互斥路径，不能共用结论。
2. 读取目标所有父级分支完整 `paramsValue`，按结构化控制流核对；同时检查同级另一分支，追到各自最终写库动作。
3. 给修改方案前证明：本次操作满足该分支条件、分支执行目标节点、最终写入出现异常的表和字段。缺任一项写“未确认命中分支”，不得让用户修改。
4. 并行分支先按 [report-contract.md](report-contract.md#涉及具体页面交互时的强制分支对照) 展示触发条件、本次路径、最终调用和写入字段；不能因节点名相近、字段相同或同组就认作同一路径。
5. 有只读样本时，用操作时间、记录 ID、`lastModificationTime` 反证最终写入；不用另一分支生成 C# 解释当前样本。

## 修改后仍复现与安全还原

- 用户反馈“按方案改了仍复现”时停止追加修改，先重读被建议位置、同级分支和最新样本；先前定位错时明确错误分支，仅给该位置精确还原及真正命中路径的证据。
- 还原参数只能来自修改前发布快照、草稿备份或明确展示的原始配置。缺原始证据时标记无法安全还原，不凭记忆补参数。
- 修改与还原必须给动作／分组显示名称、画布显示行、节点显示名称和上下相邻可见节点；标识与显示名称配对，细则见 [report-contract.md](report-contract.md)。
