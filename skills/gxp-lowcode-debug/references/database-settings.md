# Look / Write 统一数据库设置

仅在用户要求查看或调整连接设置时使用。本机 stdio 工具 `database_settings` 和 `python scripts/database_settings.py` 进入相同的设置流程；HTTP MCP 不提供此入口。未配置数据库时仍可打开设置。

| 操作 | 行为 |
| --- | --- |
| `status`（默认） | 返回非敏感当前设置、配置来源及 revision；不连接数据库，不读取密码给模型。 |
| `open` | 打开本机设置窗口，用户修改地址、端口、库名和 Look/Write 各自账户，密码隐藏输入并保存在操作系统凭据库。 |
| `update` | 模型提交用户明确指定的非敏感字段和最新 `expected_revision`；先校验和测试，成功后原子保存共享配置。 |

`changes` 仅允许 `host`、`port`、`database`、`look_user`、`write_user`。地址或库名未提供时保留原值；缺少必要值时向用户集中补充，不从项目源码、旧缓存或示例中猜目标。任何密码、完整连接串和凭据存储内容均不可放进工具参数、聊天或日志。凭据缺失或需要更换时使用窗口。

Look 和 Write 共用地址、端口和库名，各自账户和既有授权边界继续生效；插件专属超时、编译器、源码和运行目录设置保留。旧配置可继续读取，用户通过新入口保存后使用共享配置，不需要手工改两个插件的配置文件。

旧 `scripts/configure_connection.py` 及其平台包装脚本在共享配置存在时打开统一窗口，避免把改动写入已被覆盖的旧连接文件；未采用共享配置时继续原配置流程。

设置保存会检查 revision，拒绝覆盖另一窗口刚保存的配置；冲突时重新读取 `status`，按用户原意重做本次指定字段。有旧编辑流程、审批或执行尚未结束时阻止切换：说明阻塞状态，沿已有流程完成或由用户明确处理，不自动取消、释放或清理。连接测试失败保留原配置，不反复尝试相同失败目标，也不为通过测试降低账户安全设置。

保存成功后再进行新的诊断或编辑；原证据按环境重新核对，不能把旧库结论当作新库当前事实。账户安全、显式编辑启用、编译、人工审批、保存后核对保持原有要求。修改配置不代表已经保存、发布或验证业务修复。
