# GXP 精确排查输出契约

## 问题结论优先与版本状态

诊断类输出先按下方问题格式给出结论和位置，再在修改方案前或验证状态中写：

```text
动作身份：<公共动作/表单动作，名称，code，RefId；表单动作补页面 ID 和表单名>
发布同步状态：已同步 / 存在未发布草稿改动 / 当前副本缺失
运行副本：发布副本
草稿修改是否影响运行：否
证据级别：静态设计 / 只读数据 / 历史发布快照 / 浏览器运行证据 / 运行样本
验收边界：<例如未执行真实提交或业务成功验证>
```

不要写“草稿版/发布版是两个独立版本”。它们是同一动作的可编辑副本与运行副本。

## 完整问题：默认紧凑格式

诊断类回答第一行必须是 `问题1：<一句话结论>`。先给结论和精确位置，再给版本状态；不要先堆排查过程。同一问题涉及多个动作、分组或节点时使用 `位置1`、`位置2`，每个位置完整输出，不写“同上”。

```text
问题1：<一句话结论；证据不足时写候选或待确认>

位置1：
动作：<code>／<动作显示名称>
RefId：<ref_id>
分组：<分组显示名称>／<group_key>
画布<1-based>／索引<0-based>
节点：<node_key>／<节点显示名称>
类型：<elementKey>
当前：<完整条件、字段映射或当前缺失字段>
生成 C#：<独立行号及实际生成内容；候选映射要注明候选>

位置2：
动作：<code>／<动作显示名称>
RefId：<ref_id>
分组：<分组显示名称>／<group_key>
画布<1-based>／索引<0-based>
节点：<node_key>／<节点显示名称>
类型：<elementKey>
当前：<完整条件、字段映射或当前缺失字段>
生成 C#：<独立行号及实际生成内容>

下游约束：<读取端/更新端依赖的完整条件、异常或状态流转>
只读数据：<记录数量、关键字段和实际值>
失败机制：<把创建端、读取端和数据值串成因果链>

修改：
<动作 code／节点 Key：字段或条件改成什么；新增节点给出显示名称、插入锚点和上下相邻节点>

生命周期/保留项：<首次值 → 中间更新 → 完成后回写；明确哪些字段不能删除>
历史数据：<是否需要受控回填；只读诊断不得执行回填>
验证状态：<静态通过/数据吻合/运行未验证/运行通过>
```

没有对应证据的可选段落可以省略，不要输出空占位。跨动作字段生命周期必须列全创建端、读取端、更新端和实际数据值；只列一个节点不得下最终结论。

动作和分组必须写显示名称，并在同一行附带 code/Key。节点 Key、RefId、索引和生成 C# 行用于精确复核，不能单独替代显示名称、画布行及当前配置。要求用户修改时还要给上一、下一可见节点；存在同名节点时给完整条件或字段映射消歧。

## 涉及具体页面交互时的强制分支对照

用户描述点击组件、选择成员、字段留空或批量编辑时，在任何画布修改方案前先输出：

```text
用户实际操作：<原始交互>
运行输入特征：<关键组件值/事件参数>
分支1：<完整条件> -> <调用动作> -> <最终写入字段>
分支2：<完整条件> -> <调用动作> -> <最终写入字段>
本次命中：分支1 / 分支2 / 未确认
命中证据：<父级 paramsValue、运行样本时间/ID、最终写库证据>
```

`本次命中` 为“未确认”时禁止输出要求用户执行的修改步骤。用户反馈“按方案改了仍复现”时，先检查同级分支；确认先前改错分支后，只输出错误位置的精确还原和真正命中分支的证据，不得继续叠加新改动。还原参数只能引用修改前发布快照、草稿备份或用户提供的原始配置，不得猜测。

## 保存草稿后的复核

```text
问题N：草稿已修复 / 部分修复 / 草稿修改未生效

位置：<分组、画布行/索引、节点 Key、类型>
草稿当前条件/映射：<完整值>
草稿生成 C#：<独立行号；注明候选或精确行>

当前草稿：<设计 ID、修改时间、data/C# 哈希>
当前发布：<设计 ID、发布时间、data/C# 哈希>
发布同步状态：已同步 / 存在未发布草稿改动
运行副本：发布副本
草稿修改是否影响运行：否
结论：<线上是否尚未生效；是否只完成静态检查>
```

保存草稿但未发布时，不得写“线上已修复”。

## 发布后的复核

```text
问题N：发布已生效 / 部分修复 / 发布修改未生效

位置：<发布副本中的分组、画布行/索引、节点 Key、类型>
发布当前条件/映射：<完整值>
发布生成 C#：<独立行号；注明候选或精确行>

当前发布：<设计 ID、发布时间、data/C# 哈希>
当前草稿：<设计 ID、修改时间、data/C# 哈希>
发布同步状态：已同步 / 存在未发布草稿改动
运行副本：发布副本
草稿修改是否影响运行：否
结论：<静态发布检查结果；无样本时写未执行运行验证>
```

哈希一致不能代替节点内容核对，也不能代替真实运行验证。

## 动态异常

```text
异常时间：<用户提供的时间；未提供则写未提供>
运行发布快照：<设计 ID、发布时间、是否历史快照>
生成 C# 精确行：<异常栈行及上下文>
对应画布候选：<分组、画布行/索引、节点 Key、类型>
当前副本同步：<当前发布 vs 当前草稿，独立于历史快照>
结论：当前发布问题 / 仅历史发布存在 / 草稿已修但未发布 / 证据不足
```

草稿永远不能列入运行异常候选。没有异常时间时，多个发布快照只能按证据评分列候选，不能把最高分直接说成确定快照。

## 结论用语

- `已同步`：当前草稿与当前发布内容相同，仅此而已。
- `存在未发布草稿改动`：草稿内容不同，线上仍用发布副本。
- `部分修复`：并行位置中仍有未修项。
- `条件性风险`：存在机制但没有当前失败证据。
- `未执行运行验证`：只完成设计或数据静态检查。
- `浏览器运行证据`：来自用户显式授权并开启的相关页签；必须写明页面、请求和复现边界。
